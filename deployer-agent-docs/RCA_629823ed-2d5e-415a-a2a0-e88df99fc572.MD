# RCA — Redeploy failed at build_image (ECR push denied: registry image limit)

## Deployment
- Deployment: `vendor-workflow-sys` (`61a3e24d-3672-43f1-84b9-c24db8591f9f`)
- Template: `fastapi_react_mongo_shadcn_base_image` (farm / cloudflare frontend), arm64, tier_0
- Failed run: `629823ed-2d5e-415a-a2a0-e88df99fc572` (redeploy)
- Prior failed run, same cause: `ed597573-8895-4cdd-bb4b-8b4db4bfd5e3`
- Live/active run (unaffected): `3485b8f5-a60e-4827-b9a7-ca4bc8dd8852` (success) → https://vendor-workflow-sys.emergent.host

## Symptom
`build_image` step failed. Envelope `failed_step: build_image`, `kind: deploy_failed`, `retryable: false`.

## Root cause
The Docker build compiled successfully; the failure is at the **image push** to AWS ECR:

```
ERROR: failed to push 287883095218.dkr.ecr.us-west-2.amazonaws.com/customers-app:629823ed-2d5e-415a-a2a0-e88df99fc572:
denied: The repository with name 'customers-app' in registry with id '287883095218'
already has the maximum allowed number of images which is '100000'
(type: TerminalCloudBuildFailure, retryable: false)
```

The shared ECR repository `customers-app` (AWS account `287883095218`, region `us-west-2`) has reached AWS's hard ceiling of **100,000 images**. New image pushes are denied until images are pruned. This is a **platform-level, shared-registry capacity** condition — it is independent of this app's source code, dependencies, Dockerfile, or any deployment manifest. It reproduced identically on two consecutive redeploys (11:02 and 10:48 UTC).

## Why this is not fixable from this deployment
- Not a source fault: the build reached the push phase, so code/deps/imports all built. An eph-pod repro is not applicable.
- Not a manifest fault: no `Dockerfile` / `nginx.conf` / `entrypoint.sh` / `config.yaml` change can alter the push target's existing image count. A `create_deployment_manifest` fix would not affect it.
- Not retryable: AWS marked it `retryable: false`; the registry remains full, so `resume_pipeline` would fail identically. No retry was fired.

## Remediation (Platform / Emergent infra)
1. Prune the shared `customers-app` ECR repo in account `287883095218` (us-west-2) — delete untagged/old images or apply an ECR lifecycle policy to keep image count below 100,000.
2. Once capacity is freed, re-trigger the redeploy of `vendor-workflow-sys`.

## Impact
None to end users. The failed redeploys were never promoted; the previous successful run (`3485b8f5-...`) is still live and serving at https://vendor-workflow-sys.emergent.host.
